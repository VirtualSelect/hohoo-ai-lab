# 单写者的一轮对话：本地整合参考

本轮整合代码随2026-11-13质量修订发布；历史运行记录中的本地分支标识保留。不是线上助手、模型评测或新的崩溃实验。原 Demo 11 的历史结论与固定版本不改。

复用 Demo 11 的 `ContextBudget`、`TurnJournal`，把以下顺序放进 `TurnFlow`：

```text
检查取消和期限 → 查询已提交ID → 选取请求窗口 → 单次发送
    → 检查取消和期限 → 验收完整纯文本 → 再检查 → 提交完整问答
```

同 ID 同问题在重开日志后复用原答案；同 ID 不同问题在发送前拒绝。窗口裁剪只改变请求，不删除磁盘历史。写入失败后本协调器不可继续使用，应结束并重开日志恢复。

## 本地执行

需要 Java 8、Python 3 和已有 Gson 2.10.1；没有 Maven 插件下载、模型密钥或新依赖。

```sh
python demos/14-turn-flow/run.py --java-home /path/to/jdk8 --gson /path/to/gson-2.10.1.jar --out demos/14-turn-flow/out/my-run
python demos/14-turn-flow/audit.py demos/14-turn-flow/out/my-run --verify-sources
```

请替换两个本机路径，输出目录必须不存在。运行器编译两份原组件和本目录Java代码，仅绑定 `127.0.0.1` 的随机端口；HTTP响应是带 `fixture:` 前缀的固定规则，不是模型回答。测试适配器拒绝公网URL，不读取凭证。

查看 `results.json`、`requests.json` 和各场景 `.log`：前者列出观察结果，后者保留实际接收的合成请求，日志按完整帧独立验证。`protocol.json`在运行前冻结；`manifest.json`记载源码字节指纹和基线提交，明确新代码未提交，不冒充已归档版本。修改源码后，`--verify-sources`会拒绝旧产物。

## 先看这三个结果

- `lost`：服务端读完一份POST后不发回复。客户端拒绝候选，旧轮仍在；这不能证明服务端没有做事，也不能自动换ID重试。
- `cancel-after`：完整回复到达后、提交检查前标记取消。一份请求已经发生，候选没有落盘。不是传输层立即中断，也不是撤销远端执行。
- `project-not-delete`：旧轮退出请求窗口，但日志仍保存它。请求只含最近一轮，磁盘保留三轮。

## 明确的边界

仅一个协调器、一个拥有者线程使用一个日志；不能通过创建多个协调器绕过这一约定。取消和期限是检查点语义：标志在最后检查与写盘之间变化时，不能撤销已经提交的记录。不是硬实时期限或生产级并发/连接池取消。

回复契约仅验证非空纯文本及512字节上限，不证明事实正确。HTTP测试适配器另限4096字节、严格UTF-8；不作为真实提供商协议适配器。一次应用调用不等于远端恰好执行一次。

`RetryBudget`只用于此前明确可安全重试的读取示例；这里不把GET重试循环搬到生成POST。适配器禁用自动跳转并用固定长度流式写入，`lost`场景核对实际只收到一份POST。

`deadline-after`使用受控单调时钟，不报告真实延迟；`commit-io-poisons-flow`使用真实的关闭通道写入错误，不是断电或磁盘损坏验证。原 Demo 11 的实际子JVM异常退出证据继续单独阅读。
